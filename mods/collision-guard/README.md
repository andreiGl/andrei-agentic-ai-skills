# collision-guard

For several Claude sessions in one project: asks before editing a file another session changed in the last 30 minutes, and shows a banner with what the other sessions are working on.

## How it works

Every session publishes `~/.claude/collision-guard/<project root, non-alphanumerics as dashes>/<sessionId>.json`: the task (first line of the last prompt), its task-list steps, `isWorking`/`startedAt`/`updatedAt`/`isEnded`, and the paths and times of its Edit/Write/NotebookEdit calls from the last 30 minutes. A session writes its record on every change and every 15 seconds as a heartbeat, and reads the others every 5 seconds. A record silent for 90 seconds counts as gone; ended records stay 24 hours (their recent edits still warn), then are removed.

**The dialog**: before an Edit, Write or NotebookEdit (subagents too), the mod resolves the path with `$.fs.stat(path, { resolve: true }).realPath` and looks for the newest edit of that file by another session within 30 minutes. If one exists and the person has not already approved that same edit, it asks:

> Another session changed src/app.ts 4 min ago: "Refactor the app module" (session 3f2a1b9c), in progress. Edit it here anyway?

with options **Proceed** / **Move to a worktree** / **Cancel**:

- **Proceed** - the edit runs; that exact edit is remembered per path, so it is not asked about again (a newer edit asks again).
- **Move to a worktree** - the edit is denied with instructions to use the EnterWorktree tool, bring over the changes already made for this task, and redo the edit there.
- **Cancel**, or the dialog dismissed - denied with "do not edit this file; stop and ask the user".
- Typed text (the "Other" field) - denied with "the user said: <text>".
- If the check itself fails, the edit goes ahead: the guard never blocks on its own errors.

**The banner** (stacks above the prompt, below other bands): "Another session is working in this folder", then one line per live session: `● in progress|waiting for input|done <task> · now: <current step> · changed <up to 3 files> · <id8>, seen 8 s ago`. *In progress* = working now; *waiting for input* = stopped with unfinished steps; *done* = stopped otherwise. A toast fires when a new session joins.

Not covered: edits through shell commands or an external editor; sessions in other folders (a worktree is another folder); sessions not running the mod.

After `/clear` (new session id): the record starts over under the new id with the old edits carried over, and the old record is marked ended with its edits dropped - the conversation never collides with its own changes.

## Rebuild from a prompt

Paste this into a fresh Claude Code session; it re-creates the mod end to end (sources, tests, checks, install):

```text
Build a Claude Code mod named "collision-guard". Load the plugin-authoring skill first and follow it: write the mod in the dev folder the skill names, check every call against that build's API types, and run validate, test and strict tsc until all three pass.

The mod has two parts: a guard on edit tools, and a banner above the prompt. State lives in atoms (self, others, cleared); each session publishes its own record file, sessions never write each other's.

Records: every session writes ~/.claude/collision-guard/<projectKey>/
<sessionId>.json, projectKey = the session root with every non-alphanumeric replaced by '-'. The record: { sessionId, root, task (first line, clipped at 120, of the last real prompt - prompt.submit where e.command is undefined and e.isMeta is falsy), steps (the task list), isWorking, startedAt, updatedAt, isEnded, edits: [{ path, at }] }. Write on every change and every 15 seconds as a heartbeat ($.clock.every(5000, ...) with a tick counter writing every 3rd tick); read the others every 5 seconds. A record silent 90 s is not alive; an ended record is kept 24 h (its recent edits still warn) then deleted (rm -f) by readers when stale.

The guard, on tool.call for Edit, Write and NotebookEdit (matcher-free hook; check e.tool):
1. Take the path from e.file_path or e.notebook_path, resolve it with $.fs.stat(path, { resolve: true }) - use stat.realPath when present, else the raw path (new files).
2. Re-read the other sessions' records (never trust the 5-second-old cache here) and find the newest edit of that exact path by another session within the last 30 minutes.
3. If one exists and the person has not already approved that very edit (cleared[path] >= that edit's time means approved), ask with $.ui.ask(question, { options: ['Proceed', 'Move to a worktree', 'Cancel'], header: 'Collision' }) - question reads "Another session changed <short path> <ago>: \"<task>\" (session <id8>), <state>. Edit it here anyway?" where state is 'in progress' (isWorking), 'waiting for input' (stopped with unfinished steps) or 'done'. Dismissal counts as Cancel.
4. Answers: Proceed -> record cleared[path] = the other edit's time and run the edit (return next(e)). Move to a worktree -> return { deny } telling Claude to use the EnterWorktree tool, bring over the changes already made for this task, and redo the edit there. Cancel -> return { deny } telling Claude not to edit the file and to stop and ask the user. Any other answer (typed text) -> return { deny } ending "the user said: <text>".
5. After an edit runs without error or deny, append { path, at } to this session's edits (one entry per path, entries older than 30 min dropped).
The whole hook gets .catch(($, e, next) => next(e)): a failure in the check never blocks an edit.
The hook also tracks the task-list tools the same way the banner needs them (mcp__ccd_turn__update_plan / wrap_up / TodoWrite / TaskCreate / TaskUpdate, arguments flat on e), and turn.start/turn.complete set isWorking (main thread only, e.agentId undefined). On session.end mark the record isEnded (except reason 'clear': the next id carries the edits over and the old record is ended with edits dropped).

The banner, a ui.render hook on { component: 'AbovePrompt' }: start with const below = await next(e) and return the banner above it, so other mods' bands survive; yield to the survey (e.props.hasSurvey). Read the other records; on a fresh load before the first read, read them directly in the draw (a draw may not write $.state - schedule the catch-up write with $.clock.after(0, ...)). Show nothing when no live session. Otherwise a warning-colored bold title ("Another session is working in this folder", or "<N> other sessions are working...") and one line per live session: "● <state> <task>" with the state in claude/success/warning color, then dimmed " · now: <current step> · changed <up to 3 files, newest first, relative to root> [and N more] · <id8>, seen <ago>". A toast "Another Claude session is working in this folder: <task> (session <id8>)" once per newly-seen live session.

Shape it as hooks/register.tsx (the hooks), hooks/logic.ts (pure helpers: projectKey, recordEdit, recentEditBy, shouldAsk, liveOthers, workState, formatAgo, shortPath, firstLine, denyReason, the task-list transforms, parseRecord), types/index.d.ts (PluginState: self, others, cleared; exported SessionRecord, EditRecord, Step), tests/logic.test.ts (edit recency, the cleared-memory rule, liveness, work states, deny texts) and tests/guard.test.tsx (mock fs.list/fs.read with one other session's record, drive $.tool.call on Edit for each dialog answer and assert run/deny, mount the AbovePrompt banner on terminal and desktop and assert its lines). Follow the skill's rules: helpers taking $ are top-level, never declare a variable named on, annotate update() arrow return types, no dynamic import().

When validate, test and tsc pass, copy the mod to ~/.claude/mods/collision-guard/ (leave out .claude-plugin/types/ and tsconfig.json) and run claude plugin install collision-guard@local-mods.
```
