# plan-progress

A side panel with the goal, phase, checklist, progress bar and elapsed time of Claude's current plan; an All tasks view across sessions; a chime when a turn ends.

## What it shows

**This session tab**: the goal (from `/goal <condition>`, a proposed goal, or the first line of the prompt that started the plan), the phase line (`researching › planning › building › testing › auditing`, current one highlighted), a `████░░` progress bar with percentage, `done/total`, elapsed time, and `working` / `waiting for you`. Each checklist item reads `✓` done, `▶` current, `○` not started.

- The panel opens by itself the first time a plan is worth showing (a goal set, or 2+ checklist items); `/plan-progress` reopens it.
- Phase comes from the current step's wording (test/verify -> testing; review/audit/security/lint -> auditing; plan/design -> planning; read/find/explore -> researching; implement/write/fix -> building), else from the tool in use (Read/Grep/WebFetch -> researching; Edit/Write -> building; Bash running tests/tsc/clippy -> testing; review skills -> auditing).
- The clock stops when all steps are done, with a "Plan complete" toast. A new checklist after a finished plan starts the clock over; a `/goal` goal survives.

**All tasks tab**: other sessions' plans. Each session publishes `~/.claude/plan-progress/<sessionId>.json` on every change and turn start/end and deletes it on end or `/clear`; the tab re-reads the folder every 5 seconds and shows sessions updated within 6 hours that have a plan, hiding ones finished more than 30 minutes ago.

**Chime**: after each turn that was not aborted, `assets/done.wav` plays (0.33 s, A5 -> E6; generated by the script in the rebuild-prompt section). If the asset cannot play, it falls back to `afplay /System/Library/Sounds/Glass.aiff`. `/plan-progress sound off|on` silences it; the setting persists.

## Commands

- `/plan-progress` - open the panel (this session). `/plan-progress all` - open on the All tasks tab. `/plan-progress sound on|off` - the turn-end chime.
- `/goal <condition>` - set the goal; `/goal clear` - drop it. (The engine's own command; this mod observes it.)

## Checklist sources

Works with whichever task-list tool the build uses: the desktop app's `mcp__ccd_turn__update_plan` (`items` replaces, `advance`/`done`/`start` move) and `mcp__ccd_turn__wrap_up` (checks everything off), and the terminal's `TodoWrite` (whole list) and `TaskCreate`/`TaskUpdate` (by id). Tool arguments arrive flat on the `tool.call` event.

Paste this into a fresh Claude Code session; it re-creates the mod end to end (sources, tests, chime, checks, install):

Keep the script outside the mod folder when you run it.

Shape it as hooks/register.tsx (the hooks), hooks/logic.ts (pure helpers: the checklist transforms per tool, plan lifecycle withItems/EMPTY_PLAN, phase matchers, progress/bar/formatting, visibleOthers/parseSummary), types/index.d.ts (PluginState: plan, lastPrompt, view, others, isWorking, isSoundOn; exported types Plan, Item, SessionSummary, Phase), tests/logic.test.ts (the checklist transforms, lifecycle, phases, formatting, the visible-others filter) and tests/pane.test.tsx (drive mcp__ccd_turn__update_plan through $.tool.call with mocked ui.open, then mount the Pane on terminal and desktop and assert the bar, the ✓/▶ items and the tabs).
